Это клиентский компонент моста для пересылки сообщений из WhatsApp в Telegram. Проект использует Playwright для автоматизации сессии WhatsApp Web, парсинга новых сообщений из групповых чатов и их пересылки на кастомный бэкенд для дальнейшей обработки и отправки подписчикам в Telegram-боте.

Этот проект не является самостоятельным и работает в тесной связке с бэкенд-сервером и Telegram-ботом.

🚀 Архитектура системы
Общая схема работы наглядно демонстрирует взаимодействие всех компонентов системы:

mermaid

graph TD
    A[👤 Пользователь в WhatsApp] -->|1. Отправляет сообщение в группу| B(🌐 WhatsApp Group);
    B -->|2. Обнаруживается парсером| C{🤖 Playwright Parser (Этот проект)};
    C -->|3. Парсит сообщение и форматирует в JSON| C;
    C -->|4. Отправляет POST-запрос с Bearer токеном| D[⚙️ Backend Server + TG Bot];
    D -->|5. Проверяет токен авторизации| D;
    D -->|6. Определяет категорию и находит подписчиков| D;
    D -->|7. Отправляет сообщение через Aiogram| E[📢 Пользователь в Telegram];
✨ Ключевые возможности
Автоматический вход: Использует QR-код при первом запуске и сохраняет сессию в профиле для последующих автоматических входов.
Мониторинг непрочитанных сообщений: Эффективно отслеживает появление новых сообщений в любых чатах.
Надежный парсинг:
Извлекает текст сообщения, автора и время.
Корректно обрабатывает "сгруппированные" сообщения от одного автора, где метаданные указаны только у первого сообщения в блоке.
Безопасная отправка на бэкенд: Передает структурированные данные в формате JSON на указанный webhook URL, используя Bearer токен для аутентификации.
Механизм "Парковки": После обработки всех чатов скрипт переходит в специальный "Чат ожидания", чтобы "погасить" индикаторы непрочитанных сообщений и избежать их повторной обработки в следующем цикле.
Стабильность: Скрипт устойчив к динамическим изменениям DOM в WhatsApp Web, так как он сначала собирает названия непрочитанных чатов, а затем находит элементы заново перед каждым кликом.

⚙️ Установка и настройка
1. Клонирование репозитория
Bash

git clone https://github.com/your-username/your-parser-repo.git
cd your-parser-repo
2. Создание виртуального окружения и установка зависимостей
Рекомендуется использовать виртуальное окружение для изоляции зависимостей проекта.

Bash

# Создание виртуального окружения
python -m venv venv

# Активация (Windows)
.\venv\Scripts\activate

# Активация (macOS/Linux)
source venv/bin/activate

# Установка зависимостей (если есть requirements.txt)
pip install -r requirements.txt

# Или установка вручную
pip install playwright aiohttp python-dotenv qrcode
3. Установка браузеров для Playwright
Playwright требует установки браузерных движков. Выполните команду в терминале:

Bash

playwright install
4. Настройка переменных окружения
Создайте файл .env в корневой директории проекта и заполните его по следующему шаблону:

env

# URL вашего бэкенда, который принимает POST-запросы
BACKEND_URL="http://127.0.0.1:8000/incoming"

# Секретный токен для авторизации. ДОЛЖЕН СОВПАДАТЬ с токеном на бэкенде!
INCOMING_WEBHOOK_TOKEN="your_super_secret_token_12345"
BACKEND_URL: Полный адрес эндпоинта вашего бэкенд-сервера.
INCOMING_WEBHOOK_TOKEN: Секретный ключ, который парсер будет отправлять в заголовке Authorization. Критически важно, чтобы это значение было идентично тому, что используется для проверки на бэкенде.
5. Подготовка WhatsApp
В вашем аккаунте WhatsApp (на телефоне или в веб-версии) создайте или закрепите чат с названием "Чат ожидания". Этот чат используется скриптом для "парковки" и предотвращения повторной обработки сообщений.

▶️ Запуск
После выполнения всех шагов настройки, запустите главный скрипт:

Bash

python main.py
При первом запуске: В терминале появится QR-код. Отсканируйте его с помощью вашего мобильного приложения WhatsApp (Настройки -> Связанные устройства -> Привязка устройства).
Последующие запуски: Скрипт будет использовать сохраненную сессию из папки playwright_profile_py и должен войти автоматически.
💡 Как это работает
Парсинг сообщений (parse_message.py)
Первое сообщение в блоке: WhatsApp помещает метаданные (время, дата, автор) в атрибут data-pre-plain-text. Парсер ищет этот атрибут, извлекает из него данные с помощью регулярного выражения и сохраняет их в кэш.
Сгруппированные сообщения: У последующих сообщений от того же автора нет этого атрибута. Парсер использует данные об авторе из кэша, сохраненные на предыдущем шаге.
Текст сообщения: Текст извлекается из дочерних <span> элементов внутри блока с классом .copyable-text.
Формат данных, отправляемых на бэкенд
Парсер отправляет на BACKEND_URL POST-запрос со следующим JSON-телом:

JSON

{
    "wa_chat_id": "Название чата в WhatsApp",
    "wa_author": "Имя автора сообщения",
    "wa_body": "Текст сообщения",
    "is_group": 1,
    "timestamp": 1678886400,
    "wa_name": "Имя автора сообщения",
    "wa_number": "Неизвестно"
}
❓ Устранение неполадок
Ошибка ❌ Ошибка отправки на бэкенд (статус 401) или (статус 403):
Проверьте, что INCOMING_WEBHOOK_TOKEN в .env файле парсера в точности совпадает с токеном на бэкенд-сервере.

Ошибка Connection Refused или Timeout при отправке:
Убедитесь, что ваш бэкенд-сервер запущен и доступен по адресу, указанному в BACKEND_URL. Проверьте настройки файрвола.

Скрипт не может найти чаты или другие элементы:
WhatsApp Web периодически обновляет свой интерфейс, что может сломать CSS-селекторы. Откройте веб-версию, используйте инструменты разработчика в браузере (F12) и найдите новые селекторы для нужных элементов.

Скрипт постоянно просит отсканировать QR-код:
Удалите папку playwright_profile_py и попробуйте заново. Это полностью сбросит сессию. Убедитесь, что у скрипта есть права на запись в директории, где он запущен.

Ошибка ⚠️ Не удалось найти чат 'Чат ожидания':
Убедитесь, что чат с таким названием существует в вашем WhatsApp и он не в архиве. Рекомендуется закрепить его вверху списка для надежности.
